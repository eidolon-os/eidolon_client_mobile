# Host 身份、首次交付与运行时发现的解耦

状态：2026-09-11，方案已按最新讨论重写，核心改动已提交至 eidolon_ops：`a6eb5a7`（`refactor(ops): decouple deployment identity and bind first delivery`）。没有重置当前 Pi5，没有修改 Mobile、ESP32、Admin 或 SDK 的运行时协议。

本文替代此前以“新增 Ops profile”为主要修复的方案。新增独立实例仍需独立材料，但不能让部署配置成为运行时身份的权威来源。

## 1. 名词与已验证根因

当前有两类不同的密钥，不能因名字都含 host 而合并讨论：

- SSH 客户端密钥和 SSH host key：用于部署连接及确认部署目标。Mobile 与 ESP32 不使用它们。
- `host_identity.ed25519`：产品身份密钥。虽然当前首次交付由 Ops 生成并投放，它在 Host 上用于签名发现信息；Host ID 是其公钥的 SHA-256 前 20 个十六进制字符，加 `ehost-` 前缀。它不是仅用于部署的 SSH 密钥。

`Eidolon-xxxxxx` 是 Host ID 的短显示名，不是另一种硬件身份。直接删除产品身份密钥或将其替换为 MAC，会破坏已有签名、手机配对和相关运行时地址。

此前新 Pi5 在 `192.168.100.15:9002` 提供的公钥，与 Mobile 保存的旧 Pi5 完全相同；均对应 `ehost-980046b6704894461dfb`。这不是型号相同或 IP 变化导致的合并。具体复制材料的历史操作尚未还原，不能断言是移盘还是某次部署。

代码确认的两个缺口：

1. 普通更新仍读取工作站的产品私钥，用来推导运行时名称和检查板端；这使本应只更新代码的操作依赖首次交付材料。
2. 首次交付材料按配置目录持有，缺少已经交付给哪块板的约束；复用同一 profile 更换 SSH 目标，不能等价于新增独立 Host。

## 2. 最终职责边界

| 部分 | 负责什么 | 身份依据 |
| --- | --- | --- |
| Ops 首次交付 | 安装软件、投放独立身份与初始化材料、验证目标板 | 经现有 SSH 信任连接读取的本机硬件事实；只在交付阶段使用 |
| Ops 普通更新 | 更新代码及版本对应的产品配置，验证和保留板端状态 | 板端既有公开身份及已建立的 Owner 状态；不要求工作站持有产品私钥 |
| Host 运行时 | 持有产品身份与业务状态，提供签名发现信息和授权服务 | Host 本地的产品身份；不读取 Ops 的 profile、交付记录或 SSH 凭据 |
| Mobile / ESP32 | 发现候选地址，验证身份，按既有流程添加、配对和连接 | 现有产品公钥、签名与授权协议 |
| Owner 签发 | 首次初始化、明确授权的身份重建等操作 | 保持现有离线根签名密钥边界；普通部署不参与签发 |

由部署工具生成一次凭据，不代表运行时要依赖部署工具。解耦的是工具与状态的所有权，不是删除产品认证。

本轮不改变生产模式缺少身份时拒绝启动的规则，不将它替换成“缺文件就自动生成新身份”。不将 Owner 根签名密钥搬进普通 Host 服务。

## 3. 各场景实际取得什么

| 场景 | 能取得的信息 | 用途与规则 |
| --- | --- | --- |
| 尚未安装 Eidolon | 经 SSH/本机读取硬件标识；没有 Eidolon 发现服务 | 首次交付区分物理板；不能指望手机扫描到尚不存在的 Eidolon 协议 |
| Pi5 首次交付 | 设备树板载序列号及平台类型 | 生成交付指纹；不从序列号派生私钥。本轮已在当前 Pi5 实测读取成功 |
| 其他 Linux 板 | 优先设备树序列号，否则有效的 DMI product UUID | 使用平台实际提供的永久标识；缺失或占位值明确拒绝，不悄悄取第一张网卡 |
| Mac 首次交付 | IOPlatformUUID | 同一交付约束；不使用当前联网接口的 MAC |
| BLE 广播扫描 | 名称、地址、RSSI、服务标识 | 仅发现候选，不能仅凭广播名判断已添加 |
| BLE 进一步识别 | 读取现有 GATT endpoint，验证签名及公钥 | 推导 Host ID，与保存记录匹配；手机不需要拿到板载序列号 |
| LAN 扫描 | mDNS 等取得地址、端口和服务名称 | 再读取现有签名 commissioning endpoint；与 BLE 使用相同产品身份规则 |
| NetworkManager Wi-Fi 扫描 | SSID、信号、安全属性；其 AP 对象可提供 BSSID | 选择接入网络。AP 的 BSSID 属于热点，不是 Pi 的板号 |
| 重启、换 IP、切换网卡、换热点 | 地址可能变化，产品身份保留 | 保持同一 Host，重新发现可验证的连接地址 |
| 同型号新板 | 硬件不同，首次交付必须使用独立产品材料 | 产生不同公钥与 Host ID，Mobile 按现有流程识别为新 Host |
| 同 Host 的 TLS 信任变化 | 产品公钥可能相同，TLS pin 不同 | 仍是同一逻辑身份；继续使用已有信任验证流程，不自动伪装成新 Host |

NetworkManager 的本机 Device MAC、永久 MAC 和扫描到的 AccessPoint BSSID 是不同字段。硬件标识只解决部署目标的区分；产品公钥解决跨 BLE、Wi-Fi、有线网络的同一逻辑身份。

参考：[NetworkManager Wireless Device](https://networkmanager.dev/docs/api/latest/gdbus-org.freedesktop.NetworkManager.Device.Wireless.html)、[AccessPoint](https://networkmanager.dev/docs/api/latest/gdbus-org.freedesktop.NetworkManager.AccessPoint.html)、[Raspberry Pi 硬件文档](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html)。

## 4. 已实施的改动

### 普通更新只消费板端公开身份

- 复用现有 `deployment-identity` 观察：检查 Owner 数据库、anchor、公开目录的一致性，保留原有文件哈希检查。
- 从既有 Owner 目录中持久化的 Host 专属 URI 读取公开 Host ID，严格验证格式。目标通过既有 SSH 信任连接认证；不是相信网络扫描到的任意 hostname。
- 公共名称的推导不再需要私钥。更新时将观察到的公开身份传入已有 materializer，保留单一配置渲染实现。
- 不增加对“运行中的 Local API 必须能响应”的部署依赖；公开目录在板端持久保存。
- 切换前仍验证板端身份与受保护材料没有变化；身份、TLS、Owner、内部凭据和配对不会随普通更新重新签发。

### 首次交付检查物理目标

- 复用现有注入式 Host agent，增加只读硬件观察。Mac 本地交付与 SSH 交付共享同一个观察实现。
- 使用现有私有材料根目录中的 `host_delivery.json` 记录公开 Host ID 与硬件指纹。它是交付记录，不是新的运行时身份、全局注册中心或 generation。
- 同板重试验证已有记录；不同板复用相同材料，在上传产品私密材料前拒绝。记录不会被静默重绑。
- 复用现有互斥和原子文件写入，避免并发交付把同一份材料绑定给不同板。
- 已使用但缺少硬件证据的旧身份，不自动绑定当前目标；普通更新继续可用，独立新板使用新的初始化材料。
- 明确的身份重置沿用原事务，旧交付记录与旧身份材料一起退役，失败回滚仍使用原机制。
- 交付记录留在 Ops 工作站，不投放到 Host。运行时不新增硬件检查、部署记录读取或协议字段。

### 运行时发现保持现有协议

不改变 Host ID 算法、签名 endpoint、Owner/Claim、Mobile 注册表或 ESP32 配网协议。独立材料使新 Host 自然具有新公钥，手机无需通过 MAC 或 IP 猜测是否是新板。本轮没有修改手机扫描页或 TLS 恢复交互。

## 5. 兼容性与明确限制

- 无 Ops 工作站、无部署私钥参与运行时的要求，沿用现有 Host 本地持有身份的设计；普通更新对工作站私钥的额外依赖已解除。
- 旧 Host 不自动旋转身份、不自动生成硬件绑定、不强制重新配对。
- 缺少历史硬件证据时，无法可靠判断一份旧状态最初属于哪块板。不能为了显示成“新主机”，在 Mobile 端凭新 IP 改写身份。
- 交付检查针对正常 Ops 流程内的误复用。它不宣称能阻止绕过流程复制全部私钥和数据库，也不提供硬件安全模块级的抗克隆证明。
- 整机备份、恢复和显式换板迁移仍属于此前已登记的后续能力；本轮没有拼接局部备份来声称整机恢复已经可用。
- 本轮没有增加新的“创建 Host profile”界面。首次交付发现目标不同会明确拒绝复用；独立实例仍使用既有初始化流程和独立私有目录。

## 6. 当前 Pi5 的状态纠正与代码改动分开

当前 Pi5 已经带有产品状态，不能仅替换一个 Host ID 或私钥。2026-09-11 只读统计为：`companions` 3 行、`hub_device_directory_v1` 6 行、`controller_grants` 6 行。这是表记录数量，不表示全部当前有效或在线。

本次没有清除这些数据、重新签发当前 Pi5 身份或重装 APK。上述代码不会自动把当前已经重复的身份改成新的身份，因此不能把“新板现在已在 Mobile 显示为新 Host”列为已验收。

当前板若要变成独立空白 Host，需要通过已有完整重置/首次安装流程建立新 Host/Owner；旧 Mobile 记录保留，设备和 Controller 重新加入新 Host。它会影响上述当前状态，不能作为一次普通代码更新的隐含副作用。
