# 「我的 Eidolon」体验优化实施方案

评审日期：2026-09-10。代码基线：Mobile `019839c`。

本版替代此前基于 `dcdf2e8` 的方案和基于 `bc7dfaa` 的追加更正；不再保留互相冲突的实施条款。初版见 [历史评审](my-eidolon-ux-review.md)。本方案的首页、设置、状态展示与发现资料层级已在工作区实施；完成范围及验证边界见第 10 节。

## 1. 结论与范围

保留现有业务能力，优先修正错误状态文案，再逐步合并主机详情与管理首页，统一对话导航入口，整理设置。此次不重做对话、设备接入、主机发现、网络定位或身份存储；这些链路已有大量新增实现，必须作为迁移约束。

用户要求继续有效：主机列表保留 IP、机型和人类可读资料；监控显示 CPU 型号、各核心标识及占用、NPU 型号及可获取的各核心占用、内存、Eidolon 服务/进程占用，以及运行入口路径和启动信息。监控仅保存页面内当前快照，刷新间隔为代码常量 10 秒，无用户设置项。不支持的指标明确说明，不用 0 或推测数据代替。

“监控数据不用保存”只约束遥测历史，不删除主机资料、身份密钥、Claim、Owner 信任或设备接入断点。这些持久状态承担正常使用和恢复能力。10 秒也只约束监控；设备准入现有 3 秒状态观察不应被统一改慢。

以下结论来自代码和现有测试，不是本轮真机操作的观察。优先级按实施顺序和影响评估。

```text
  ...主机数量动态显示，不硬编码两台或三台...

点击主机 → 书房主机                              设置
┌───────────────────────────────────────────────────┐
│ 机型 / 配置 · 地址及其来源                         │
│ 管理连接状态 · 最近验证时间                       │
│ [进入对话]                                        │
│ 打开准备页，选择应答伙伴和对话方式                 │
├───────────────────────────────────────────────────┤
│ 主机监控          CPU / NPU / 内存 / 服务与进程   │
│ 伙伴              列表、详情、任务、对话记录       │
│ 记忆              Owner 记忆库及伙伴视角           │

│ 驾驶舱            伙伴、设备与活动关系             │
└───────────────────────────────────────────────────┘
```

上述配置为示意，以主机真实返回数据为准。首页不嵌入第二套监控轮询，不为装饰性数值增加请求。主机列表保留本地资料与现有前台验证；监控实时数据继续由监控页负责。

设置分为“主机资料与本机备注”“我的称呼”“网络 / 更换 Wi-Fi”“管理手机（授权管理设备）”“诊断信息”“安全与恢复”。安全区域保留重新认领及从本机列表移除，明确前者会撤销所有已授权管理手机，后者只影响本机列表。

首页立即呈现已知资料和对话导航，不等待 Workspace。管理模块按各自真实依赖加载；进入对话也不代表可以立即开聊。自动读取沿用无 BLE 的 LAN 路径，靠近主机读取/BLE 恢复放在明确的连接或网络操作中；保留原有 BLE 回退能力，不让日常浏览触发新的权限请求。

发现页保留“可添加 / 已添加 / 暂未识别”分组。首层展示名称、已知机型配置、当前发现地址或上次连接地址、添加状态；详细资料展开。未知资料说明连接后才能取得，不为补齐机型而偷偷认领或写注册记录。已发现不等于已通过管理认证，已添加也不等于在线。

不引入五个底部标签，不在本轮重排所有伙伴/记忆详情，不新增“从伙伴详情直接开聊”业务链路。对话诊断中的监控和设备快捷入口有独立上下文，保留并复用同一页面。

## 6. 不可改变的关键行为

### 对话与身份

- 首页“进入对话”是导航；产品页“开始对话”是动作，不属于需要去掉的第三个重复入口。
- 伙伴和模式均选好才可开始。PTT、半双工、全双工及其静音/打断/释放手势规则全部保留；准备期不入房，接通确认前不发送麦克风音频。
- `choose/chooseMode` 保存页面草稿，不立即持久改绑。通话中更换先确认结束；取消保留原通话，确认后回准备页，用户再次开始才执行关联确认与入房。已有“确认接入并开始对话”仍保留其明确表达的复合意图。
- 当前 `_continueConversation` 经 `_confirmCompanion` 调用 `management.device`，必要时 assign，再确认主机结果。Owner 目录/Device 配置可独立读取，不代表整个开始对话过程不依赖管理能力。文案与测试不得承诺“管理服务完全不可用也一定可开聊”。
- 沿用应用级 MobileDeviceRuntime、串行 open、revision 和可等待的幂等 close。同 Owner 多 Host 复用设备；跨 Owner 独立密钥、DeviceInstance、Claim、handoff 和待批准登记。切换回来保留原状态，禁止按 IP 或每个 Host 新建身份。
- 退出对话、切换 Host、后台收音、诊断子页覆盖各有生命周期；按原规则处理，不能以统一 dispose 简化。借用控制器不销毁父级，页面自建控制器需在对话关闭后释放。

### 网络与设备接入

- OwnerAuthorityRoutes 按当前 registry 路由，TLS 仍校验 Owner 根和签名域名；外部 authority 使用正常 DNS。公开 HEAD 探测成功只证明该 TLS origin 可达，不证明业务服务就绪。
- 竞速/重试定位可以复用现有机制；已发送的登记、批准、manifest/config 等业务请求不透明重放。请求结果未知要沿用业务查询、命令身份和恢复规则，不能由页面按钮生成新请求规避。
- 同一 origin 并发读取共享定位；退出一个等待者不能取消其他页面仍使用的请求。网络变化和旧结果的取消归原会话/路由对象负责，新首页不得用全局 close 误伤其他所有者。
- 配网两次 SoftAP 接入有真实网络依赖：首次读取身份并 prepareOwner → 回到 Host 可达网络取 voucher → 再接入设备配置网络。可改阶段文案，不能删除其中一次连接或将 Host 请求移入不可达时段。
- 网络提交终态、准入批准和 ClaimActive 不是同一个成功；保留持久断点和只读观察。页面恢复不自动再次批准，清理连接失败不把已提交成功改写为失败。
- 主机管理已连通、Owner API 可达、LiveKit/Room 可用、音频会话已接通是不同事实。移动端不改写服务端动态地址，不通过“重连”偷偷重启服务；换网后的媒体恢复另按端到端证据验收。

## 7. 分阶段实施与退出条件

### A. 先修正文案和展示，暂不合并路由

修正“尚未开放”、记忆未知与空数据、Workspace 设置完成文案；折叠技术信息但保留资料。统一两个导航按钮名称为“进入对话”，保留原 handler 和产品页动作。补针对错误、空值和真实禁用原因的 widget 断言；不为纯间距变化增加机械测试。

退出条件：现有路径、业务请求次数和副作用不变；文案不能声称未经验证的可用性。该阶段可独立提交/回退。

### B. 拆分首页加载状态，再迁移导航

先增加测试，覆盖管理认证成功但 Workspace/home/设备读取慢或失败、授权中途失效，以及双击、取消和返回；再让已认证模块及时展示。监控不依赖概览，但仍要求有效管理认证；不能为了早显示而把页面局部状态当成新的授权真相。

建立明确的主机页面作用域，复用 Controller/Runtime/Owner 路由，不更改底层协议。将两个原导航入口归并到首页；同一时刻只导航一次。正常进入、首次设置完成、发现页连接已保存主机、恢复完成四条路径分别适配。身份变化/撤权错误直达真实恢复入口，不再假定上一页存在。

退出条件：第 5 节每项功能都可达，控制器所有权和请求取消测试通过，之后才移除旧中转。旧路由删除可以回退，但不回退数据格式或清理用户身份。

### C. 设置归位与真机验收
