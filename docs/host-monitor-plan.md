# 主机监控实施计划

## 已确认的产品范围

连接 Host 后，将「主机运行状态」替换为只读「主机监控」。保留连接、认证与主机选择基础能力；移除本页的设备、Controller、活动历史、会话撤销和服务控制。其他业务页面不在本次删除范围。

页面顺序：主机名 / IP / 当前读取状态 / 更新时间 → CPU 和 NPU 型号与逐核占用 → 内存和磁盘 → Eidolon OS 服务与进程及启动详情。

```text
┌ 主机监控 ─────────────────────────────── 刷新 ┐
│ Host 名称 · 地址 · 状态 · 更新时间 · 每 10 秒刷新 │
├ CPU · 芯片型号 ───────────┬ NPU · 设备型号 ─────┤
│ CPU 0 · 型号 · 占用条 / % │ 核心 0 · 型号 · %   │
│ CPU 1 · 型号 · 占用条 / % │ 核心 1 · 型号 · %   │
│ ……                       │ 或显示不可用原因    │
├ 内存 · 已用 / 总量 · 可用量 ────────────────────┤
├ 磁盘 · 路径 · 已用 / 总量 · 可用量 ─────────────┤
├ Eidolon OS 服务与进程 ────────── 按 CPU / 内存 ┤
│ 服务名 · 状态 · CPU · 内存 · 进程数          ▾ │
│   服务配置路径 · 工作目录 · 用户 · 主 PID       │
│   进程名 · PID · CPU · RSS                   ▾ │
│     可执行文件 / 运行入口文件或模块             │
│     工作目录 / 脱敏命令 / 启动时间 / 运行时长    │
└────────────────────────────────────────────────┘
```

窄屏时 CPU / NPU 改为上下排列；服务和进程按需展开，长路径换行并可复制。

- CPU：芯片型号、核心型号、逐核占用，支持时显示频率；整机与单核都以各自满载为 100%。Load 不替代 CPU 使用率。
- NPU：设备型号和逐核占用；驱动未提供的数据明确显示不可用，不平均分配整体读数、不虚构型号或温度。
- 内存：总量、可用量及使用比例。磁盘：路径、总量及可用量。
- 服务：状态、CPU、内存和进程数，支持按 CPU / 内存排序。展开查看进程 PID、父 PID、用户、可执行路径、入口文件或模块、工作目录、脱敏启动命令、启动时间和运行时长，以及服务配置路径、退出状态（可获取时）。源码不可推断时明确区分入口模块和源码文件。
- 仅当前快照，不落盘、不保留历史、不提供趋势。CPU 速率计算所必需的前一次累计计数只暂存内存，进程退出后丢弃；不构成历史记录。
- 刷新间隔由代码常量配置，当前为 10 秒；界面无间隔选择器。首次进入及恢复前台立即读取；后台、被其他路由覆盖、退出页面时暂停；请求不重叠。
- 请求失败时明确显示不可达或读取失败；不得用连接时的旧状态声明当前正常。当前屏幕最多保留上次快照并注明已过期；无任何历史存储。

## 实施顺序

1. 扩展共享 System 契约，新增结构化监控快照。
2. Linux 主机端从 procfs / sysfs / systemd 采集；macOS 使用 psutil / supervisord。根据服务目录或实际服务主 PID 识别归属，不执行用户提供的命令。读取有界，错误按指标隔离；对敏感参数采用遮蔽策略，不读取进程环境变量。
3. 经 eidolond → Admin → Controller 认证的 Management API 转发；接口设置不缓存，更新 OpenAPI 并重新生成客户端类型。
4. Flutter 接入快照并重构页面；删除旧页冗余依赖，完成定时轮询、生命周期、空态、错误态和窄屏布局。
5. 验证采集计算、PID 重用、缺失硬件、脱敏、认证转发、10 秒轮询、后台暂停、并发去重与布局；运行契约生成检查、相关测试及 Flutter 分析、APK 构建。
6. 在可用的已连接 Android 设备上覆盖安装并检查页面；主机在线部署与真实 NPU 指标需以可达环境实测结果为准。

## 验收标准

- 页面真实读取所连接 Host，全部数据带同一快照时间；未提供和 0% 清楚区分。
- CPU / NPU 各核心型号与占用一眼可见；刷新无整页闪烁、滚动与展开状态保留。
- 服务与进程显示实际采集的路径和启动信息，敏感值不离开采集端。
- 无历史数据存储、趋势图、刷新间隔选择器以及原页面其他管理功能。
- 旧 Host 未提供接口时提示升级；部分采集失败不使整页失效。

### 真实 Host 验收结果

重新连接后，平板通过原有 Host 身份校验找回 Eidolon-6b1f15，当前地址为 192.168.1.32；该地址属于当前 Mac。10.42.0.2 的 RK3588 台架板为另一台环境，不部署到该板。

已补充 macOS/supervisord 适配：CPU 逐核累计计数、内存、磁盘及基于主 PID / 父子关系的服务进程归属，使用 macOS 条件依赖 psutil；CPU 使用率按相邻计数计算，服务内存明确标注 RSS 合计，避免与 Linux cgroup 口径混淆。macOS 未提供可读取的 NPU 型号及逐核接口时明确显示不可用。Linux/RKNPU 适配仍保留。

已重启当前 Host 的 eidolond、admin-api 和 local-api 使新增接口生效。System 实际接口返回 200，读取 Apple M3 Pro 的 12 个 CPU 核心及 18 个服务。平板经原有认证链路成功显示实时 CPU、内存、磁盘和服务占用；滚动展开 agent 服务及主进程，已确认配置路径、可执行文件、运行入口文件、工作目录、用户、PID、启动命令、启动时间和运行时长可见。自动刷新后读数变化，展开详情仍保留。

本次真实设备验收覆盖 macOS Host；Linux/RKNPU 采集已通过解析及计算测试，但没有在运行中的 RK3588 Eidolon Host 上完成端到端验收。当前 Mac 不显示虚构的 NPU 型号、逐核占用或大小核型号。
