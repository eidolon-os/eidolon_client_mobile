# 「我的 Eidolon」体验评审与优化方案

> 此为历史初版，保留供比对，不能直接作为当前实施依据。当前以 2026-09-10 基于 `019839c` 重写的 [最终方案](my-eidolon-ux-final-plan.md) 为准；其中已纳入统一发现、网络迁移、设备状态收敛、三种对话模式及多 Owner 身份隔离，并区分“进入准备页”和“具备开聊条件”。

评审范围：主机列表、主机详情、连接后的首页，以及监控、驾驶舱、伙伴、记忆、设备、管理手机、网络和恢复入口。

依据：当前 Flutter 页面、导航与状态处理代码，结合本次及前面在平板上观察到的界面。属于体验走查，尚未进行独立用户可用性测试；优先级和方案是设计判断，不是用户行为统计。本轮仅形成方案，不修改功能实现。

## 建议结论

合并「主机详情」与「连接后的我的 Eidolon」，让主机列表点击后直接进入该主机的首页。首页聚焦“这是哪台主机、现在能做什么、哪里需要处理”；连接认证作为首页状态处理。将网络、管理权限、恢复等低频操作集中到设置。

保留主机监控、伙伴、记忆、对话和设备等已有能力，去掉重复入口、无效中转页和常驻工程说明。驾驶舱保留为可选的「运行关系图」，与主机资源监控明确分工。

## 页面结构

```text
我的 Eidolon（主机列表）
├─ 主机 A：备注名 / 机型与主要配置 / IP / 连接状态
├─ 主机 B：备注名 / 机型与主要配置 / IP / 连接状态
└─ 添加主机

点击一台主机 → 主机首页（自动连接，不经过中转页）
├─ 主机身份与状态：名称 / 机型 / IP / 最近更新
├─ 需要处理：仅在异常、待设置或待批准时出现
├─ 快捷入口：开始对话 / 主机监控
├─ 当前概览：伙伴、设备、可用能力
├─ 次要入口：运行关系图
└─ 底部导航：概览｜伙伴｜记忆｜设备｜设置

伙伴 → 伙伴详情 → 对话记录 / 任务与进度 / 该伙伴视角的记忆 / 伙伴设置
记忆 → 当前主机上的记忆；可切换伙伴视角
设备 → 设备列表 → 设备详情 / 应答伙伴；添加设备使用分步流程
设置 → 主机资料 / 网络 / 我的称呼 / 授权管理设备 / 诊断信息 / 安全与恢复
```

手机使用底部导航，平板可用左侧导航，功能与名称一致。应用启动默认仍展示主机列表，保留主动选择多台主机的能力；进入某主机后保持其上下文。切换主机时重置子页数据、会话与待提交动作，不能把上一台主机的状态带到下一台。

## 子页面具体调整

### 对话与伙伴

- 首页对话按钮说明当前将由谁应答；对话页持续显示当前伙伴和主机上下文。
- 初次对话需要批准或关联时，用“让这台平板接入主机 → 选择应答伙伴 → 开始对话”的分步流程呈现，避免在入口常驻 Device / Hub / Companion 等实现说明。
- 从伙伴页开始对话只能在系统确实支持定向到该伙伴时提供；不能进入另一位默认伙伴的对话却沿用选中伙伴标题。需要改变设备关联时明确告知，不静默重绑。
- “收起伙伴”保留关联设备受影响的说明；把它放在伙伴设置底部，不作为日常主操作。

### 记忆、对话记录与任务

- 三者保留不同意义：记忆是整理后的内容，对话记录是原始交流，任务是可跟踪的执行进度。不要仅因都像“历史”就合并。
- 主机级记忆入口与伙伴视角入口共用同一个页面和筛选机制，始终展示当前范围；不是删除一个入口，而是统一功能实现与作用范围。
- 任务目前从伙伴进入，先保留这一真实范围。若后续增加首页跨伙伴任务汇总，需要真实聚合能力，不能只把默认伙伴的任务改名为“全部任务”。
- 尚未读取、没有内容、读取失败三种状态分别处理；已有内容刷新失败时保留并标记过期。

### 设备与授权管理设备

- 设备卡片显示“名称 / 是否可用 / 应答伙伴”，设备 ID、挂载 revision 放技术详情。
- 添加设备作为单个入口，内部区分待批准设备与需要配网的新设备；保留底层两阶段过程，不把配网成功表述为设备已可用。
- 设备移除、解除伙伴关联、撤销管理权限、从列表移除主机必须使用不同措辞和影响说明。
- 同一台手机可能兼具管理与对话用途；界面解释用途，底层身份和授权边界保持分离。

### 网络与恢复

- 离线时仍可查看已保存机型与地址、改备注、进入网络设置或从列表移除主机。
- 普通失败：先“重试连接”，必要时“重新查找”；不直接建议清除身份。
- 身份变化：解释检测到不同主机身份，提供检查身份/恢复授权的具体入口，不自动接受新身份。
- 授权失效：引导重新获得管理权限；不能靠重试按钮循环。
- 版本不支持：说明需要更新哪一侧（能够确定时），不要混成网络失败。
- 恢复涉及撤销所有授权时必须保留影响确认；优化入口不能削弱原有身份验证和权限检查。

## 状态与刷新规范

| 状态 | 页面表现 | 主要动作 |
|---|---|---|
| 尚未检查 | 展示已保存资料，注明地址来源 | 自动开始检查或点击连接 |
| 正在连接 | 主机资料保留，相关模块加载 | 返回/取消仍可用 |
| 已认证连接 | 显示可用入口，各模块独立加载 | 使用功能 |
| 部分模块不可用 | 仅对应模块提示原因 | 重试该模块 |
| 无法连接 | 保留旧资料，标注最后成功时间 | 重试连接 / 网络设置 |
| 身份不一致或权限失效 | 专用状态与说明 | 对应安全恢复流程 |
| 尚未完成初始化 | 显示设置步骤及下一步 | 继续设置 |
| 初始化完成 | 替换设置路由，进入真正首页 | 无额外“进入我的 Eidolon”中转 |

刷新默认复用现有连接；连接确实失效时才重新认证/定位。列表资料检查采用有界并发，避免一台不可达主机拖慢后面所有主机。页面隐藏时暂停可取消的读取和轮询；切换页面不应反复重建会话。该项是架构调整目标，不能只更换按钮文字。

## 实施顺序与验收

1. 第一阶段：合并主机详情和连接页；去除“尚未开放”误标；修正未知/空数据/异常的表达；身份校验后立即呈现可用功能。优先改善进得去、找得到、看得懂。
2. 第二阶段：引入主机内导航；归并设置、网络和安全恢复；统一子页的主机/伙伴上下文；精简列表和首页文案。
3. 第三阶段：整理伙伴详情、设备接入、运行关系图入口与平板布局；结合实际使用反馈调整快捷入口顺序。

验收以实际任务为准：

- 从主机列表进入监控最多两次点击；自动连接不需要额外确认。
- 打开一台在线主机时，身份验证成功后不被记忆、设备等非关键模块拖住整个首页。
- 用户在任何主机子页都能判断当前操作的是哪台主机，返回列表路径明确。
- 新建主机完成初始化后直接进入首页，已有主机不再看到初始化完成确认步骤。
- 没有把“未连接”写成“尚未开放”，没有把“没读到”写成“没有数据”。
- 旧版本、断网、身份变化和授权失效均有准确而不同的下一步。
- 网络重试不清空可保留的已显示内容；监控滚动、展开及 10 秒刷新约定保持。
- 伙伴、终端设备与管理权限操作范围明确；多主机切换不存在错误主机写入。

建议用两台主机、一个旧版/离线场景、多个伙伴、一个待批准终端和一个授权失效场景进行验收。此方案不要求删除已有业务数据、不改变身份协议，也不把全部业务重写作为第一阶段前提。
